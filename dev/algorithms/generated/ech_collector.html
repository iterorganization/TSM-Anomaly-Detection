ech_collector

Note

This page is generated automatically from the ech_collector algorithm package [1].

Description [2]

Gyrotron collector intershot anomaly detection

ech_collector is an unsupervised intershot detector for the thermal behavior of a gyrotron collector [1]. It compares a completed pulse with a history of previously observed pulses and flags thermal profiles that lie outside the dense operating regimes represented in that history. The detector is intended to highlight unusual pulses for review; an outlier is not, by itself, evidence of a physical fault.

Inputs

Each input represents one complete pulse on a common time grid.

  • The target signals are the collector thermocouple time series.

  • The context contains the cathode-voltage signal named by Vk_signal.

  • The cathode voltage must cross Vk_threshold, because the interval between its first and last above-threshold samples defines the pulse duration.

  • The configured frequency must match the sampling frequency of the target data used for feature extraction.

The detector also requires a representative reference history containing pulses with the same target and context signals. Reference pulses need not have the same duration, but all cache rows must be produced with the same signal configuration and TSFEL feature settings.

How it works

  1. The detector calculates the active pulse duration from the cathode-voltage signal.

  2. TSFEL extracts the configured feature domains independently from every target signal, and the features are concatenated into one fixed-length representation of the pulse.

  3. The current representation is combined with the cached representations of the reference pulses and standardized.

  4. Low-variance features and features whose absolute Spearman correlation with pulse duration exceeds spearman_threshold are removed so that the comparison focuses on thermal behavior rather than pulse length.

  5. PCA projects the remaining features into the smallest space that retains the fraction of variance selected by min_explained_var.

  6. DBSCAN groups dense regions in that space, and the current pulse is anomalous only when DBSCAN assigns it the noise label -1.

This approach is most sensitive to global changes in the collector heating cycle, such as atypical ramp-up, a missing or distorted plateau, drift, or unusual cool-down behavior. Short or subtle disturbances confined to one thermocouple can be diluted by the feature aggregation.

Configuration notes

The example configuration (example_config.json) documents the expected gyrotron signals and provides starting preprocessing and DBSCAN values. The most important settings are:

Setting

Purpose

Vk_signal, Vk_threshold

Select the context signal and threshold used to measure pulse duration.

frequency, domain

Configure TSFEL sampling frequency and feature domains.

var_threshold, spearman_threshold

Control feature filtering.

min_explained_var

Set the fraction of variance retained by PCA when given as a value between 0 and 1.

eps, min_samples

Define the DBSCAN neighborhood radius and minimum dense-neighborhood size.

reference_state.path points to the state file used to track the raw history and its derived feature cache. On first setup, the conventional paths are history/manifest.json and cache/manifest.json, relative to the reference-state file. Place the historical pulses as framework-format *.h5 files in the corresponding history/ directory before calling setup(). With check set to full, setup refreshes the history hashes from those files and rebuilds missing or stale cache entries; fast trusts the existing history manifest.

The reference history should cover the normal operating regimes that the detector is expected to accept. Changing the history or the feature and clustering parameters can change both the DBSCAN classification and the score, so the parameters should be validated against the intended operating data.

Running the detector

Instantiate the class with a configuration file, call setup() once to prepare the reference cache, then call detect() for each completed pulse:

from tsmadalg.algorithms.ech_collector import ECHCollector
from tsmadkit.io import read_hdf5_input_data
from tsmadkit.signals import SignalSet

detector = ECHCollector("config.json")
detector.setup()

payload = read_hdf5_input_data("pulse.h5")
signals = SignalSet(payload, detector.signal_spec)
result = detector.detect(signals)

print(result.to_dict())

Relative paths in the configuration are resolved from the directory containing the configuration file.

Result and interpretation

The returned AnomalyResult provides:

Field

Meaning

is_anomaly

True when the current pulse receives DBSCAN label -1; otherwise False.

scores["dbscan_isolation_score"]

The current pulse’s distance to itsmin_samples-th nearest sample in PCA space, divided by eps.

A score at or below 1 means that the current pulse has enough samples within the DBSCAN radius to be core-like. A larger score indicates greater local isolation, but the Boolean result remains authoritative because a DBSCAN border point can be non-anomalous even when its own score exceeds 1.

The detector does not return a fault class, a responsible thermocouple, or an anomalous time interval. Its output should therefore be interpreted as a whole-pulse screening result that calls for inspection of the original signals and operating context.

Implementation

Intershot anomaly detection for gyrotron collector thermocouples.

This algorithm relies on a configured reference state. The reference state should be associated with a history/ folder containing past gyrotron pulses in the expected HDF5 input format; during setup, those pulses are transformed into the reference distribution used for detection.

Each historical pulse is represented by TSFEL features from the target signals and the pulse duration derived from the cathode voltage window. At detection time, the current pulse is transformed in the same way, compared with the historical reference pulses, decorrelated from pulse duration, reduced with PCA, and classified with DBSCAN. A pulse is anomalous only when DBSCAN marks it as noise with label -1.

The ‘name’ key in the configuration is a string that identifies the algorithm. The ‘parameters’ key in the configuration is a dictionary where each item becomes an attribute of the instance. detect(data: SignalSet) → AnomalyResult[source]

Detect whether the current pulse is anomalous relative to reference pulses.

The new gyrotron pulse and historical reference pulses are standardized, filtered by variance, filtered again to remove features correlated with pulse duration, projected with PCA, and clustered with DBSCAN. The new pulse is considered anomalous only when its DBSCAN label is -1. Non-negative labels identify normal cluster membership.

The anomaly score is s(x) = d_k(x) / eps, where x is the new pulse in reduced feature space, d_k(x) is its distance to the k-th nearest pulse, k is DBSCAN’s min_samples value, and eps is DBSCAN’s neighborhood radius. Values up to 1 indicate enough local density to be core-like; larger values indicate weaker local density and stronger anomaly.

Parameters:

data (SignalSet) – New gyrotron pulse to compare against the historical pulses prepared from the configured reference state.

Returns:

Detection result with is_anomaly set from the current pulse’s DBSCAN label and scores["dbscan_isolation_score"] containing s(x).

Return type:

AnomalyResult
