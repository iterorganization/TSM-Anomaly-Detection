class tsmadkit.anomaly_detection.AnomalyDetection(configuration: str | Path | dict)[source]

Bases: ABC

Abstract base class for anomaly detection algorithms.

The purpose of this class is to provide a common interface and configuration- driven setup for anomaly detectors. It handles parsing a JSON configuration, exposing the algorithm name and user parameters as attributes, and offering a hook (setup()) for model loading or other pre-execution setup.

Subclasses must define a __version__ class attribute (e.g. "0.1.0") and implement detect() to define the anomaly detection logic and return an AnomalyResult. The TSM POZ application (C++) calls _tsm_poz_execute() instead, which wraps detect() and returns EPICS-compatible, serializable values.

Typical usage:

  1. Instantiate with a configuration file or dictionary.

  2. Call setup() once to load the model (if any).

  3. Call detect() with input data in SignalSet format or call _tsm_poz_execute() with a plain input dictionary.

Parameters:

configuration (str | Path | dict) – Configuration dictionary or path to a JSON file containing the algorithm configuration. Relative paths within a configuration file are resolved from the directory containing that file. Relative paths within a configuration dictionary are resolved from the current working directory. Absolute paths are used unchanged in both cases.

Notes

The configuration should have the following format:

{
    "name": "algorithm-name",
    "parameters": {"threshold": 0.5},
    "model": {
        "source": "scikit-learn",
        "path": "model.joblib"
    },
    "signals": {
        "targets": ["signal-a"],
        "context": ["signal-b"]
    },
    "artifacts": ["additional-data.npz"],
    "anomaly_classes": ["anomaly"],
    "reference_state": {
        "path": "reference_state.json",
        "check": "fast"
    }
}

All nullable top-level fields are optional: model, parameters, artifacts, anomaly_classes, and reference_state. signals.context may also be omitted.

The ‘name’ key in the configuration is a string that identifies the algorithm. The ‘parameters’ key in the configuration is a dictionary where each item becomes an attribute of the instance. The configuration content is hashed into config_hash, which is the same whether the configuration comes from a file or a dictionary.

Raises:

TypeError – If the subclass does not define __version__ as a non-empty string.

setup() → None[source]

Hook for loading the model (if any) and performing any pre-execution setup. The main role of this method is to ensure self.model is correctly set and the reference state (if any) is ready before detect() or _tsm_poz_execute() are called.

Default behavior:

  • If “model” is null, do nothing.

  • If “source” is one of the supported loaders (‘scikit-learn’, ‘keras’, ‘tensorflow’), load the model from “path”.

  • If “source” is “custom” or None, raise NotImplementedError. In this case, subclasses must override setup() to implement their own loading logic.

  • If “reference_state” is configured, prepare its history/cache using the configured “check” mode.

Notes

  • This method is not called automatically. It is the caller’s responsibility to call setup() once after construction and before using _tsm_poz_execute().

  • Subclasses should override setup() only when non-standard loading or additional setup is required.

  • Overriding subclasses should call super().setup() if they need the default model loading or reference state validation.

  • On first use, when the reference state’s manifests and JSON file do not exist yet, this call bootstraps all of them from the raw *.h5 files under history/; see Reference-State Management.

Raises:

  • NotImplementedError – If no custom initialization is provided for a model with a ‘source’ of ‘custom’ or unspecified, or if a reference state is configured but the subclass does not implement transform().

  • ValueError – If an unknown model ‘source’ is specified. Valid sources are: ‘scikit-learn’, ‘keras’, ‘tensorflow’, ‘custom’, or None.

  • TypeError – If the subclass’s transform() does not return a dict.

class tsmadkit.anomaly_result.AnomalyResult(*, is_anomaly: bool, scores: dict[Annotated[str, FieldInfo(annotation=NoneType, required=True, metadata=[MinLen(min_length=1)])], float], label: Annotated[str, FieldInfo(annotation=NoneType, required=True, metadata=[MinLen(min_length=1)])] | None = None, time_min: int | float | None = None, time_max: int | float | None = None, sources: list[Annotated[str, FieldInfo(annotation=NoneType, required=True, metadata=[MinLen(min_length=1)])]] | None = None, details: dict[Annotated[str, FieldInfo(annotation=NoneType, required=True, metadata=[MinLen(min_length=1)])], Any] | None = None, message: Annotated[str, FieldInfo(annotation=NoneType, required=True, metadata=[MinLen(min_length=1)])] | None = None)[source]

Bases: BaseModel

Standardized output structure for anomaly detection results.

Parameters:

  • is_anomaly (bool) – Primary decision flag indicating whether the input is anomalous.

  • scores (dict[str, float]) – Unified scoring output. For binary detectors, use {“anomaly”: s} for a single anomaly score s. For multiclass, provide per-class scores or probabilities, e.g. {“OK”: 0.92, “arc”: 0.06, “misfire”: 0.02}. Semantics (probability, margin, distance) are algorithm-defined and should be documented by the implementing class.

  • label (str, optional) – Predicted class name when the algorithm performs classification (e.g. “arc”, “misfire”, “OK”). Binary detectors may set this to “anomaly” when is_anomaly is True or omit it entirely.

  • time_min (int | float, optional) – Minimum time value in the detected anomaly window.

  • time_max (int | float, optional) – Maximum time value in the detected anomaly window.

  • sources (list[str], optional) – Signals or features that contributed most to the decision.

  • details (dict[str, Any], optional) – Algorithm-specific values that provide additional context for analysis or visualization of the result.

  • message (str, optional) – Short human-readable explanation of the decision.

Notes

Downstream systems must rely on is_anomaly for warnings and scores for an initial severity estimate. Other fields provide context only when available.

class tsmadkit.signals.SignalSet(data_dict: dict[str, ~typing.Any], signal_spec: ~tsmadkit.signals.SignalSpec, *, dtype: ~numpy.dtype = <class 'numpy.float64'>)[source]

Bases: object

Runtime container for multiple signals on a shared time grid.

SignalSet arranges incoming data according to a SignalSpec, stores values in the spec’s canonical order, and provides convenient access by signal name, positional index, and role. Signals with matching trailing dimensions are stacked into one numeric array; heterogeneous signal shapes are stored in an object array so each signal can keep its own shape.

Expected input payload:

{
    "time": [...],
    "values": {
        "sig_a": [...],              # shape: (n_samples,)
        "sig_b": [[...], [...]],     # shape: (n_samples, d)
        ...
    }
}

All signals must share the same first axis length as time (sample axis). Trailing dimensions may differ between signals.

Parameters:

  • data_dict (dict[str, Any]) – Input payload with time and values keys.

  • signal_spec (SignalSpec) – Signal roles and canonical signal ordering.

  • dtype (np.dtype, default=np.float64) – Data type used when converting time and signal values to arrays.

Top-level reference state for one configured algorithm.

A reference state ties the algorithm identity, algorithm configuration, history manifest, and cache manifest together. It owns the lifecycle that creates missing manifests, refreshes history in full-check mode, rebuilds stale cache files, and records the hashes that make later fast checks cheap.

Parameters:

  • path (str or Path) – Path to the reference state JSON file.

  • name (str) – Current algorithm name.

  • version (str) – Current algorithm version.

  • config_hash (str) – Current algorithm configuration hash.

  • signal_spec (SignalSpec) – Signal specification used to load history samples.

setup(*, check: Literal['fast', 'full'], transformer) → None[source]

Prepare the reference state, history manifest, and cache manifest.

Parameters:

  • check ({"fast", "full"}) – Check mode. "full" refreshes the history manifest from HDF5 files; "fast" trusts an existing history manifest.

  • transformer (callable) – Function used to derive cache entries from history samples.

Notes

On first use, when no reference state file, history manifest, or cache manifest exists yet, this method creates all three: the history manifest is built from the *.h5 files under history/, the cache manifest and its .npz files are built by calling transformer once per history sample, and the reference state file is written last to record what was just built.

Determine a time window around samples where a signal is above a threshold.

The returned window spans from the first sample above threshold to the last sample above threshold, optionally padded before and after.

Padding values are expressed in the same units as time.

Parameters:

  • time (np.ndarray) – 1D array of uniformly sampled, sorted time values.

  • signal (np.ndarray) – 1D array of signal values corresponding to time.

  • time_before (float, optional) – Amount of time to include before the first above-threshold sample, in the same units as time. Default is 0.0.

  • time_after (float, optional) – Amount of time to include after the last above-threshold sample, in the same units as time. Default is 0.0.

  • threshold (float, optional) – Threshold used to define the above-threshold region. A sample is considered above threshold when signal > threshold. Default is 1000.

Returns:

((tmin, tmax), (imin, imax)) where:

  • tmin and tmax are the start and end values of the padded window in the units of time.

  • imin and imax are the corresponding array indices.

Returns None if no samples are above threshold.

Return type:

tuple[tuple[float, float], tuple[int, int]] | None

Raises:
